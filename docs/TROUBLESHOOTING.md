# EKTA — عیب‌یابی و پرسش‌های متداول (Troubleshooting)

این راهنما برای Runtime 0.2 و Workspace 0.4 است. متن کامل خطا را نگه دارید؛ آخرین خط traceback به‌تنهایی ممکن است علت اصلی را نشان ندهد.

## 1. دستور Python پیدا نمی‌شود
نشانه: python: command not found یا شناخته‌نشدن فرمان در Windows.
- Python 3.11+ نصب کنید.
- Windows: py -3 --version را امتحان کنید.
- Linux/macOS: python3 --version را امتحان کنید.
- پس از نصب، ترمینال را دوباره باز کنید.

## 2. نسخه Python قدیمی است
نسخه را بررسی و از Python 3.11 یا جدیدتر استفاده کنید. محیط مجازی قبلی را با نسخه جدید بسازید.

## 3. ساخت محیط مجازی ناموفق است
نشانه: خطای venv یا ensurepip.
- مطمئن شوید Python کامل نصب شده است.
- در Linux بسته venv مربوط به نسخه Python را نصب کنید.
- پوشه .venv ناقص را پس از توقف برنامه حذف و دوباره بسازید.

## 4. نصب بسته‌ها ناموفق است
نشانه: pip timeout، TLS، DNS یا خطای build.
1. اتصال شبکه و DNS را بررسی کنید.
2. python -m pip --version را اجرا کنید.
3. python -m pip install --upgrade pip را اجرا کنید.
4. سپس python -m pip install -e . را دوباره اجرا کنید.
5. متن کامل خطا و سیستم‌عامل را ثبت کنید.

مخزن در این نسخه بسته آفلاین وابستگی‌ها را ارائه نمی‌کند.

## 5. پورت 8000 اشغال است
نشانه: خطای Address already in use.
برنامه‌ای را که از پورت استفاده می‌کند متوقف کنید یا Uvicorn را دستی روی پورت دیگری اجرا کنید:

~~~bash
python -m uvicorn ekta_runtime.api:app --app-dir runtime --host 127.0.0.1 --port 8010
~~~

سپس به http://127.0.0.1:8010 بروید.

## 6. صفحه باز نمی‌شود
- مطمئن شوید ترمینال هنوز در حال اجرای Uvicorn است.
- URL را دقیقاً با http:// و پورت درست وارد کنید.
- /health را بررسی کنید.
- اگر پورت را تغییر داده‌اید، URL رابط را نیز تغییر دهید.
- خطاهای ترمینال را بررسی کنید.

## 7. خطای Import یا پیدا نشدن ekta_runtime
از ریشه مخزن اجرا کنید و نصب editable را تکرار کنید:

~~~bash
python -m pip install -e .
~~~

در اجرای دستی، گزینه --app-dir runtime را فراموش نکنید.

## 8. داده یا مفهوم جدید دیده نمی‌شود
- آیا فایل در مسیر canonical قرار گرفته است؟
- آیا فایل Markdown و Front Matter معتبر است؟
- آیا شناسه تکراری یا فیلد نامعتبر وجود دارد؟
- آیا Runtime پس از تغییر فایل دوباره راه‌اندازی شده است؟
- آیا فایل در مسیرهای ایندکس‌شده قرار دارد؟
- آیا نوع فایل در نسخه فعلی پشتیبانی می‌شود؟

Runtime 0.2 داده‌ها را در شروع برنامه بارگذاری می‌کند؛ برای اطمینان از بارگذاری مجدد، سرور را متوقف و دوباره اجرا کنید.

## 9. جست‌وجو نتیجه نمی‌دهد
- فیلترهای کناری و فیلترهای داخل Query را بررسی کنید.
- ابتدا فقط یک واژه ساده وارد کنید.
- عبارت دقیق را از کوتیشن خارج کنید.
- kind:document یا kind:concept را موقتاً حذف کنید.
- شناسه فنی را از فایل Taxonomy یا رکورد بردارید.
- جست‌وجو فقط محتوای ایندکس‌شده را می‌گردد.

## 10. API پاسخ 404 می‌دهد
برای /api/v1/concepts/{id} شناسه مفهوم باید وجود داشته باشد. برای /api/v1/documents/{id} باید Document ID برگشتی از Search استفاده شود. Document ID را از روی نام فایل حدس نزنید.

## 11. رابط باز می‌شود اما داده ناقص است
- بررسی کنید EKTA_ROOT به ریشه درست مخزن اشاره کند.
- وجود پوشه‌های taxonomy/ و encyclopedia/ را بررسی کنید.
- خروجی ترمینال را برای خطاهای YAML/Front Matter ببینید.
- validator را اجرا کنید:

~~~bash
python tools/validate_docs.py
~~~

## 12. Git تغییرات محلی را اجازه نمی‌دهد
~~~bash
git status
git diff
git branch --show-current
~~~

تغییرات محلی را بدون بررسی حذف نکنید. پیش از Pull، Commit یا stash آگاهانه انجام دهید.

## 13. امنیت و دسترسی
اگر برنامه را روی شبکه عمومی منتشر کرده‌اید، آن را متوقف کنید. Runtime 0.2 احراز هویت و کنترل دسترسی چندکاربره ندارد و برای انتشار مستقیم عمومی سخت‌سازی نشده است. اجرای پیش‌فرض loopback را حفظ کنید.

## 14. خطای Import یا Draft در Workspace\n- پسوند فایل را بررسی کنید؛ فقط Markdown/YAML/JSON متنی پذیرفته می‌شود.\n- حجم Import نباید از ۱ مگابایت بیشتر باشد.\n- YAML باید ساختار معتبر داشته باشد؛ Markdown دارای Front Matter باید delimiter بسته داشته باشد.\n- شناسه پیش‌نویس فقط از حروف بزرگ، عدد و خط تیره تشکیل شود.\n- پوشه `.ekta/workspace/` باید قابل نوشتن باشد.\n- خطای Restore می‌تواند ناشی از ZIP خراب، مسیر traversal، symlink یا ساختار پوشه ریشه نامعتبر باشد.\n\n## 15. اطلاعات لازم برای گزارش خطا
- سیستم‌عامل و نسخه؛
- نسخه Python؛
- Commit یا تاریخ دریافت ZIP؛
- فرمان دقیق اجراشده؛
- متن کامل خطا؛
- مرحله‌ای که خطا رخ داده؛
- آیا خطا قابل تکرار است؛
- آیا از EKTA_ROOT یا پورت سفارشی استفاده شده است.

هرگز Token، رمز یا داده محرمانه را در Issue عمومی قرار ندهید.

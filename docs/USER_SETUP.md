# EKTA — راهنمای آماده‌سازی کاربر (User Setup)

این سند پیش از نصب است. هدف آن روشن‌کردن نیازمندی‌ها، انتخاب روش استفاده و آماده‌کردن محیط است؛ نصب گام‌به‌گام در USER_INSTALLATION.md آمده است.

## 1. چه چیزی نصب می‌کنید؟

EKTA Runtime 0.2 به‌همراه Operational Workspace 0.4 یک برنامه وب محلی است:
- برنامه روی رایانه شما اجرا می‌شود؛
- مرورگر فقط رابط کاربری را نمایش می‌دهد؛
- داده‌های دانش از فایل‌های مخزن EKTA خوانده می‌شوند؛
- سرویس پیش‌فرض فقط روی 127.0.0.1 گوش می‌دهد؛
- کاوشگر اصلی خواندنی است؛ میزکار عملیاتی Import را در staging و ویرایش را در قالب پیش‌نویس محلی انجام می‌دهد، بدون تغییر مستقیم دانش canonical.

این نسخه سرویس ابری میزبانی‌شده، اپ موبایل مستقل یا سیستم حساب کاربری نیست.

## 2. نیازمندی‌های پایه

| نیازمندی | وضعیت |
|---|---|
| سیستم‌عامل | Windows، Linux یا macOS؛ اسکریپت‌های موجود Windows و POSIX هستند |
| Python | نسخه 3.11 یا جدیدتر |
| Git | برای clone و دریافت به‌روزرسانی توصیه می‌شود |
| مرورگر | مرورگر مدرن با JavaScript |
| اینترنت | برای clone و نصب وابستگی‌ها در اولین راه‌اندازی لازم؛ اجرای محلی پس از نصب به سرویس ابری نیاز ندارد |
| فضای ذخیره‌سازی | مخزن، محیط مجازی Python و بسته‌ها؛ اندازه با رشد محتوا تغییر می‌کند |
| شبکه | پورت محلی 8000 باید آزاد باشد |

حداقل RAM یا فضای دیسک تضمین‌شده و بنچمارک رسمی این نسخه منتشر نشده است. اندازه مخزن بر مصرف منابع اثر می‌گذارد.

## 3. مهارت موردنیاز

برای استفاده روزمره از رابط، آشنایی با Python لازم نیست؛ نصب اولیه به اجرای دستور یا اسکریپت نیاز دارد. برای افزودن دانش canonical، آشنایی مقدماتی با Markdown، YAML، شناسه‌ها و Git مفید است.

## 4. انتخاب حالت استفاده

### حالت A — کاربر عادی
هدف: اجرای EKTA و جست‌وجو/مشاهده محتوا. نیاز: Python 3.11+، مرورگر و نسخه مخزن.

### حالت B — مشارکت‌کننده محتوا
هدف: ساخت یا اصلاح شناسنامه‌ها و اسناد. علاوه بر موارد بالا: Git، ویرایشگر متن، آشنایی با قالب‌های templates/ و اجرای validatorها.

### حالت C — توسعه‌دهنده Runtime
هدف: تغییر API، جست‌وجو، رابط یا ابزارها. علاوه بر موارد بالا: محیط توسعه Python، وابستگی‌های توسعه، آزمون‌های خودکار و آشنایی با FastAPI.

## 5. حساب‌ها و حریم خصوصی

- برای اجرای محلی و خواندن مخزن عمومی، حساب ChatGPT لازم نیست.
- برای clone مخزن عمومی GitHub معمولاً ورود حساب لازم نیست؛ برای push تغییرات به مخزن، مجوز GitHub لازم است.
- Runtime 0.2 در حالت پیش‌فرض به API هوش مصنوعی یا حساب ابری متصل نیست.
- رمز، Token، کلید API، اطلاعات شخصی یا سند محرمانه را در مخزن عمومی Commit نکنید.
- پیش از انتشار رکورد، مجوز و حساسیت منابع و داده‌ها را بررسی کنید.

## 6. واژگان مهم

| اصطلاح | معنی |
|---|---|
| Repository | پوشه نسخه‌پذیر پروژه EKTA |
| Canonical record | فایل اصلی و مرجع یک مفهوم یا دانش |
| Runtime | برنامه‌ای که مخزن را بارگذاری و جست‌وجو می‌کند |
| Workbench | رابط مرورگر برای کاوش |
| Taxonomy | رجیستری طبقه‌بندی کنترل‌شده |
| Concept ID | شناسه پایدار شناسنامه، مانند EKTA-CON-000001 |
| Document ID | شناسه مشتق‌شده سند، مانند EKTA-DOC-... |
| Branch | شاخه کاری Git |
| Commit | نسخه ثبت‌شده تغییرات |
| CI | آزمون و اعتبارسنجی خودکار |

## 7. چک‌لیست آماده‌سازی

- [ ] سیستم‌عامل و معماری دستگاه مشخص است.
- [ ] Python 3.11 یا جدیدتر نصب است.
- [ ] دستور python --version یا py -3 --version اجرا می‌شود.
- [ ] Git نصب است یا روش دریافت ZIP انتخاب شده است.
- [ ] پورت 8000 آزاد است.
- [ ] فضای کافی برای clone و نصب وابستگی‌ها دارید.
- [ ] می‌دانید کاوشگر فقط خواندنی است و Workspace 0.4 فقط Import staging و Draft محلی دارد.

## 8. ثبت نسخه

برای استفاده قابل تکرار، نسخه و Commit را ثبت کنید:

~~~bash
git rev-parse --short HEAD
git status --short
python --version
~~~

اگر از ZIP استفاده می‌کنید و پوشه .git ندارید، SHA در دسترس نیست؛ نام نسخه و تاریخ دریافت را یادداشت کنید.

## 9. مرحله بعد

به USER_INSTALLATION.md بروید. پس از اجرا، `http://127.0.0.1:8000/workspace` را برای onboarding و خودآزمایی باز کنید؛ سپس USER_MANUAL.md و WORKSPACE_GUIDE.md را دنبال کنید.

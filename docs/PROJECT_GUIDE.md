# EKTA Project Guide

## What EKTA is
A curated engineering knowledge system connecting meaning, architectural location, dependencies, implementation, alternatives, evidence, and practical use.

## Four ways to work
- **DISCOVERY:** formulate a research question, inspect primary sources, create source records, extract candidate concepts.
- **ENCYCLOPEDIA:** search canonical terms, aliases, IDs, domains, layers, and knowledge types; follow typed relationships.
- **DECISION LAB:** define constraints, criteria, alternatives, evidence, trade-offs, and decision owner; record an ADR.
- **EXECUTION LAB:** select a playbook, check preconditions, perform steps, capture outputs, verify acceptance criteria, record deviations.

These are connected views, not isolated silos. Research can create concepts; concepts inform decisions; decisions create implementation work; verification can revise concepts.

## Reading a concept
Ask: What is it and what is it not? Why does it exist? What role does it play? Which domains/layers/types apply? What are its components, mechanism, lifecycle, inputs, outputs, interfaces, dependencies, patterns, implementations, standards, trade-offs, failure modes, verification methods, and sources?

## Status meanings
- DRAFT: incomplete.
- PROPOSED: ready for review.
- RESEARCHED: sources inspected; uncertainty may remain.
- VERIFIED: specified claims have adequate evidence and review.
- IMPLEMENTED: an inspectable implementation exists.
- VALIDATED: acceptance checks passed under recorded conditions.
- DEPRECATED: retained for history, not current guidance.
- BLOCKED: progress depends on an unresolved condition.
- NOT_RUN: verification has not been executed.

Statuses are artifact- and claim-specific. IMPLEMENTED does not imply VALIDATED.

# Constraints and Assumptions Register

## Confirmed constraints
- Preserve all existing EKTA content, IDs, taxonomy counts, schemas and runtime behavior.
- The canonical repository is https://github.com/metsam-mastem/EKTA.
- Git-native, inspectable and offline-capable artifacts are preferred.
- Chat history is not the canonical project store.
- No license change or bulk external content import without a separate decision.
- Do not claim tests, runtime integration or deployment without evidence.

## Working assumptions — require review
- UPDS should be reusable across software-only, hardware-only and hybrid projects.
- The initial implementation should avoid mandatory hosted services and heavyweight databases.
- Markdown/YAML/JSON are sufficient for the first canonical document records.
- The UPDS subsystem should be extractable later through stable schemas and namespace boundaries.

## Unknowns
- Final legal license.
- Retention periods by data class and jurisdiction.
- Required regulatory profiles for future EKTA use cases.
- Final graph and search storage technology.

# Card, Deck, Gallery and Board Library

## Card families
Hardware, Software, Firmware, Data, Interface, Network, System, Module, Process, Requirement, Constraint, Decision, Test, Evidence, Material, Resource, Cost, AI Model, Agent, Tool and Document.

## Card anatomy
Stable entity ID; type/category; name; optional image/icon; selected properties; ports/interfaces; relationships; constraints; status; version; provenance and evidence links.

## Views
Mini, Compact, Standard, Technical, Visual, Game, Node, Exploded, Comparison and Document. View definitions are separate from entity records.

## Deck model
A Deck contains references to reusable entities or templates, optional sort/group rules, metadata, license/provenance and version. Starter Decks: Universal Hardware, Software Architecture, Embedded Systems, AI Systems, Network Engineering, Data Architecture, System Architecture, Process Engineering, Testing & QA and Product Development.

## Board model
A Board contains placements, optional groups, typed connectors and board-specific constraints. Initial families: Freeform, Grid, Kanban, Mind Map, Flow, Architecture, Circuit, Assembly, Timeline, Matrix, Map and Game Board.

## Gallery metadata
Category, subcategory, type, tags, source, license, version, status, compatibility and asset references. External assets must retain attribution and license evidence.

## Game mechanics boundary
Game Board may later add zones, pieces, turns, resource rules and win conditions. These optional rules must not mutate the engineering model without an explicit command.

# Cross-Layer Concept Map

| Concept | Hardware | OS/platform | Workflow/agent |
|---|---|---|---|
| Runtime | Device/processor execution context | Program execution environment and services | Workflow/agent lifecycle environment |
| Engine | Specialized computational unit | Software subsystem for a class of work | Workflow/rules/inference/orchestration engine |
| Scheduler | Instruction/resource scheduling | Process/thread scheduling | Task/job/workflow scheduling |
| Controller | Circuit or motor control | System/service control component | Flow or policy controller |
| Manager | Physical resource management | Memory/device/process manager | State/resource/task manager |
| Executor | Execution unit | Code/task execution component | Activity/tool executor |
| Worker | Processing element | Background worker process/thread | Workflow or agent worker |
| Driver | Device control/interface | OS device driver | Tool adapter (not equivalent) |
| Adapter | Electrical/protocol conversion | API/interface translation | Integration between components |
| Interface | Electrical/mechanical boundary | API/ABI/system contract | Task/agent contract |
| Bus | Electrical communication path | System communication mechanism | Message/event bus |
| Queue | Hardware buffer | OS/runtime queue | Pending task/message queue |
| Cache | Processor cache | Software/data cache | Result/context cache |
| State machine | Logic circuit state | Program/service state | Workflow/agent state |
| Pipeline | Hardware stages | Data/build pipeline | Sequential workflow stages |
| Monitor | Physical signal monitor | Metrics/logs/traces | Execution/policy monitor |

Do not assume meanings are identical across layers. Each record must define context, scope, mechanism, I/O, and boundaries.
